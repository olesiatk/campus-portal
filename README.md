# Angular Pet Project

A pet project simulating a university student-management system ("Інститут прикладної математики" — a Ukrainian-language UI). Built with Angular 22 and Angular Material, using a mocked in-memory backend so it runs with no server setup.

## Roles

The app has four roles, each with its own routed module and shell layout:

- **Admin** (`/admin`) — manages departments/streams, teachers, students, subjects, and approves registration requests.
- **Dean** (`/dean`) — department-scoped views of teachers, students, subjects, and grades.
- **Teacher** (`/teacher`) — manages their own subjects, sees only their own students and grades, and enters grades (restricted to their own subjects/students).
- **Student** (`/student`) — views their own schedule, subjects, classmates, and grades.

Routing is role-gated via `AuthGuard` + `RoleGuard` (see `src/app/app-routing.module.ts`); each role's feature module is lazy-loaded.

## Tech stack

- Angular 22 (NgModules, not standalone components) + Angular Material/CDK
- `angular-in-memory-web-api` as a mock REST backend — no real server, no database
- RxJS, Reactive Forms
- Vitest for unit tests
- A navy/pastel design system defined as CSS custom properties in `src/styles.scss`

## Getting started

```bash
npm install
npm start        # ng serve, http://localhost:4200
```

```bash
npm run build     # production build to dist/
npm test          # unit tests (Vitest)
```

## Mock data

There is no real backend: `src/app/core/services/in-memory-data.service.ts` wires up `angular-in-memory-web-api` to serve the JSON files in `src/app/core/mock-data/seed/` at `/api/...` endpoints (`/api/users`, `/api/subjects`, `/api/grades`, `/api/scheduleEntries`, etc.). This means:

- All "server-side" filtering/authorization (e.g. a teacher only seeing their own students' grades) is implemented client-side, in the Angular services.
- The seed data itself is deterministically generated by `scripts/generate-seed-data.js` (a mulberry32 PRNG with a fixed seed). Run `npm run seed` to regenerate it from scratch — this overwrites every file in `src/app/core/mock-data/seed/`.

## Project structure

```
src/app/
  admin/    dean/    teacher/    student/   — one feature module per role
  auth/                                     — login / signup (registration request)
  core/
    guards/                                 — AuthGuard, RoleGuard
    services/                               — HTTP services (one per entity) + AuthService
    models/                                 — shared TypeScript interfaces
    mock-data/seed/                         — seed JSON consumed by the in-memory API
  shared/                                   — reusable components, pipes, Material re-exports
```

## Code language convention

All code, identifiers, and comments are in English. User-facing strings (labels, snackbar messages, validation errors, day names, etc.) are in Ukrainian, since that's the application's UI language.
